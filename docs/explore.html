01 THE DEPARTURE

Your app. Its own little engine.

Put the Go library inside your app: it asks a model, runs tools, and saves the conversation. No HTTP server needed.

For a remote machine, the optional thin server is a bridge: requests go in, numbered events come back. The library still does the work.

Our pretend task: “Fix the tests in my project.”

Simulation only. No models, commands, or network calls.

02 THE WORKSHOP

Six tools.
Plenty of possibility.

The model chooses a tool; the library does the job and brings back the result. Tap a bench to see a tiny example.

Normal tool results have a default 256 KiB limit per call.

Real tools have the host user's access. This is not a sandbox. There are no built-in approval prompts; an embedding host can supply a BeforeTool approval hook.

03 THE CROSSROADS

A nudge, not a derailment.

Each session is its own conversation, with one turn at a time. Other sessions can work alongside it.

Steering saves your guidance now, then applies it before the next model request—not halfway through a tool.

Both tracks are open. Try guiding or stopping just A.

Normal completion can start a follow-up for waiting guidance. Interrupt/failure pauses it instead. Interrupt cannot undo effects already made.

04 THE MEMORY HOUSE

Pack light.
Keep the originals.

A long conversation becomes a working summary plus recent context. The original pages stay on the shelf. This is compaction, not deletion.

Main: coding explicit handoff to change

This pretend session is idle, so manual compaction is available.

History pattern-search (Go regex) finds up to 10 references per page. Then read the original context. Only this session is searched.

05 THE NIGHT SHIFT

Some things stay switched on.

A preview server can keep running after a turn—or an interrupt. Launch it with background Bash and an explicit log file, not a trailing &.

The greenhouse is quiet. A launch is not a readiness check.

Command exit, session deletion, or runtime shutdown stops owned background work. Logs stay in files, uncapped. A remote preview needs your own port forwarding.

06 THE RETURN DOCK

Pick up where you left off.

Closing your laptop only closes your view. While the remote service keeps running, it saves events before publishing them.

Return with your last event number. Replay the missed events, then follow new ones. Your client ignores duplicates by session and number.

An example cursor of 42 means: “Show me events after 42.”

A service restart is different: unfinished work is suspended until the host resumes it. The stock server can opt in with resume_on_start. Replay-allowed tools/hooks may repeat effects; unsafe carried-over calls are skipped and reported to the agent. Saved outcomes do not rerun. Stop the suspended operation before Continue if you want a new turn instead. Old processes/PIDs are never adopted.

A FEW NOTES FOR THE WALK HOME

Know what the signals mean.

OutputHere are the test results.Ordinary answers and tool output. Seeing text does not prove the turn finished successfully.

Diagnostic / warningWaiting before a model retry.A notice about the work, such as compaction, interruption, or recovery.

ErrorThat tool result is too large.A problem to act on. A recoverable tool error need not end the turn.

Not a window into hidden thoughts. “Thinking” is only reasoning text or summaries the provider exposes. sam-g does not invent hidden chain-of-thought.

Instructions travel in snapshots. Prompt-file contents stay frozen until setup or unified reload; turns and compaction do not reread them. Whole-runtime config and prompt changes require every session to be fully idle (SIGHUP in the stock server). Model-only installation can happen while chats run: active work keeps captured definitions, and new work uses the latest catalog; restart/recovery also uses latest configuration. The main model stays bound until an explicit idle model handoff; catalog changes never silently move an existing chat.

A trusted-machine workshop. No sandbox or built-in approval UI. A Go host can add approval hooks. The server is a thin remote host, not a public multi-user service. Use your existing SSH/Tailscale boundary. sam-g itself needs no Node runtime; shell tools need Bash.
